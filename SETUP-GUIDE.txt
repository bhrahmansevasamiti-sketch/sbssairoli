IMPORTANT SECURITY LIMITATIONS
1. GitHub Pages is static hosting. It cannot itself securely authenticate users or protect data. Firebase Authentication and Firestore rules provide the access control.
2. The Firebase project has Phone Authentication enabled, India SMS region configured, GitHub Pages hostname authorised, and Firestore created in production mode, according to the setup screenshots.
3. Keep Firestore rules locked until the approved data structure and server-side admin assignment process have been tested. The rules file is a proposed policy and must be reviewed against the final data model before publishing.
4. Do not place the Excel member list, member data exports, bank statements, service-account credentials, or the old static dashboard containing embedded personal data in this public GitHub repository.
5. This implementation uses SMS OTP. A phone number is an identifier, not a password.
6. Admin role must be granted using Firebase Admin SDK in a trusted server environment. Never add an admin flag from browser JavaScript or trust a role field supplied by a user.
7. Current starter portal expects member documents in `members` keyed by verified E.164 phone number, for example +919876543210. Set active=true only for approved members. The existing security rules use the verified phone claim to restrict members to their own document.
8. Do not import the Excel list until the administrator claims, rules, and final data structure are implemented and tested.
